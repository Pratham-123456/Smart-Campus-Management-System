# CRUD Coverage — all 15 tables (Phase 3)

Every operation runs browser (vanilla JS SPA) → `fetch` with session cookie → `AuthInterceptor` → REST controller → service (business rules) → JDBC repository (`JdbcTemplate`, a `PreparedStatement` per call with `?` binds) → HikariCP → Oracle 26ai `FREEPDB1`.

**Delete policy.** Academic history is never cascade-deleted. A parent delete first counts its child rows; it returns **409 Conflict** (with the counts) while children exist, **404** if the id is unknown, and only then issues `DELETE`. Rows that record history are retired *logically* with a status value instead of being deleted.

Legend: **S** = Student, **F** = Faculty, **A** = Administrator. Paths are relative to `/api`.

## Front-end wiring

| Portal | Screens / actions |
|---|---|
| Student (`student.js`) | Profile; offerings with live seats + **Register** / **Drop**; attendance %; marks `/30 /30 /50` with total out of 100, grade and **Drop**; exam schedule + **Register** / **Cancel Registration**; published results + **Apply for re-exam**; re-exam list + **Withdraw** (PENDING) |
| Faculty (`faculty.js`) | Assigned offerings; class roster with attendance % and marks with total out of 100; Classes Held, Attendance and Marks modals |
| Admin (`admin.js`, `admin-crud.js`) | Live KPI dashboard; Departments, Programs, Courses, Offerings, Students, Faculty, each with **Edit** / **Delete**; Exams with **Results** (publish/edit/delete), **Mark Completed**, **Cancel**, **Edit**, **Delete**; Published Results; Re-exam decisions; Account Provisioning; User Accounts (activate/deactivate, reset password, delete) |

Every write shows a success toast or a `[status] message` error toast. While a write request is in flight all action buttons are disabled (`API.setBusy`), which prevents double submission.
